## 2. Why it could not be attributed

`[MPR-STEP]` reported **2,638 ms** and `views seen: ['axial']`.

`_mpr_step()` had **17 call sites and every one passed `'axial'`**.
`_create_sagittal_view`, `_create_coronal_view` and `_create_3d_view` emitted
nothing. So the timing table saw 2.6 s of an 8.7 s freeze, and the single
largest component was invisible:

```
11:24:04.222  gap=4,201 ms
  toolbar_manager.py:5678 toggle_zeta_mpr
  widget.py:452 __init__
  _mpr_views.py:296 _setup_ui
  _mpr_views.py:761 _create_coronal_view
  QVTKRenderWindowInteractor.py:362 __init__
```

**Coronal alone cost more than the entire instrumented budget.** Attribution had
to fall back on the stall sampler, which tells you what the thread was doing at
one instant — not what anything cost. This exact gap was written up as
`OPEN_FINDINGS_2026-08-16.md` §2 two days earlier; this freeze is what it
predicted.

## 4. The change

Purely additive `_mpr_step()` brackets, mirroring the axial pattern at the
identical points:

| Function | Steps added |
|---|---|
| `_create_sagittal_view` | 17 (full axial parity) |
| `_create_coronal_view` | 17 (full axial parity) |
| `_create_3d_view` | 15, incl. **`gpu_raycast_mapper_ctor`** (a 575 ms sample on 08-16) and `volume_mapper_set_input` |
| `_setup_ui` | `('all', 'setup_ui')` — brackets the whole view-building phase |
| `_prewarm_mpr_reslice` | `('all', 'prewarm_reslice')` — a 488 ms sample in this freeze |

Call sites per view, before → after:

```
{'axial': 17}  ->  {'axial': 17, 'sagittal': 17, 'coronal': 17, '3d': 15}
```

The `prewarm_reslice` end marker is in a `finally` — that function returns early
when MPR is closed mid-defer, which would otherwise drop the phase and leave an
unclosed `begin` in the timeline.

No behaviour change. `_mpr_step` is unchanged, still guarded, still
kill-switchable with `AIPACS_MPR_STEP_TRACE=0`.

## 5. Guard test

`tests/code/viewer/test_mpr_step_instrumentation.py` — 20 tests, AST-based:

- every creator emits steps, **under its own view name**;
- no creator is still hardcoded to `'axial'` (the original defect, stated
  directly);
- the two dominant steps are bracketed on all three 2D planes;
- the 3D view measures the GPU ray-cast mapper ctor;
- every `begin` has a matching `end` in the same function — an unclosed phase
  makes the timeline lie rather than merely lose data;
- `_setup_ui` / `_prewarm_mpr_reslice` brackets exist, and the prewarm end is
  in a `finally`;
- behavioural: `_mpr_step` never raises, even with a broken logger.

## 6. One test needed fixing, and it is worth knowing why

`test_mpr_defer_3d_view.py::test_setup_ui_defers_only_the_3d_view` failed after
the change. It bounded its search window at a **fixed 4,000 characters** from
`def _setup_ui(`; the added brackets pushed the legacy branch's last assertion
past that boundary, so it reported

> `assert '_create_coronal_view(views_layout, 1, 1)' in ...`

which reads as *"the coronal view stopped being built"* — a frightening false
positive from an instrumentation-only change.

Fixed by bounding at the next method instead of a character count. Every
assertion is unchanged; the window is strictly more correct. Notably the very
next test in that same file already carries the comment *"Bound the window at
the NEXT def rather than a fixed character count"* — the lesson was learned once
and not applied here.
