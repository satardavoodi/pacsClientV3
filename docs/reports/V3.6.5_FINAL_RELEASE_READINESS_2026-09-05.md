# AI-PACS 3.6.5 Final Release Readiness Review

Date: 2026-09-05
Status: **BLOCKED — new build required after licensing decision**

## Executive result

The six existing 3.6.5 installers are internally coherent and contain the
cardiac MRI Flow DICOM value-multiplicity normalization fix. They are no longer
the final release candidate because the working source has changed after their
isolated snapshot. A new PyInstaller and Nuitka build is required.

The release must not be published yet. The remaining decision that changes the
customer activation contract is whether to invalidate legacy shared-secret
licenses and require reactivation under an offline public-key signature scheme.

## Cardiac MRI Flow export compatibility

The cvi42 interoperability defect was caused by standard multi-valued DICOM text
attributes, especially Image Type, being serialized as one Python-list-looking
string. The pixel payload, UIDs, geometry, and flow measurements were not the
root cause.

The correction is present at both required boundaries:

- socket ingestion normalizes affected DICOM values before the atomic write;
- DICOMDIR/media export normalizes the copied export object without changing the
  stored source object.

The current source and the prior 3.6.5 build snapshot contain identical copies
of `PacsClient/utils/dicom_vm_normalization.py`,
`modules/download_manager/network/socket_client.py`, and
`modules/dicom_media/dicomdir.py`. The PyInstaller archive and Nuitka compilation
report both contain these modules. Five focused normalization guards pass.

This proves code and package inclusion. It does not replace the remaining
clinical interoperability gate: export a representative de-identified cardiac
flow study and confirm cvi42 imports it and enables flow quantification.

## Compressed DICOM codec and legal correction

The previous proprietary build dependency set included `pylibjpeg-libjpeg`,
whose installed distribution metadata declares GPL-3.0. For 3.6.5, JPEG
baseline, extended, and lossless decoding now uses `python-gdcm==3.2.6`
(the distribution declares Apache-2.0 and bundled GDCM code carries its upstream
BSD-style terms), and JPEG-LS uses `pyjpegls==1.5.1` (MIT, with bundled CharLS
notices also applicable). The MIT pylibjpeg
OpenJPEG and RLE plugins remain.

Both PyInstaller and Nuitka specifications now declare the Python modules,
native decoder binaries, distribution metadata, and GDCM XML resources. The
release gate combines pydicom handler coverage with pylibjpeg entry-point
coverage and rejects missing native binaries. Real reference samples for JPEG
lossless, JPEG 2000, and RLE decoded and round-tripped successfully under the
project interpreter.

The installer now copies the proprietary EULA and a third-party dependency
inventory to the installed `Legal` folder. The EULA header distinguishes its
document revision from product release 3.6.5.

This engineering inventory is not legal advice. Release management must still
confirm the organization's Qt commercial license or the complete LGPL/GPL
compliance path, and preserve complete upstream license texts before public
distribution.

## Credential and license protection

EchoMind center credentials already use per-access-code authenticated encrypted
envelopes. The shipped source does not contain the prior plaintext center
credential table. This deters casual extraction but cannot make a client-held
credential secret from a determined runtime debugger.

The separate workstation License Generator still validates a symmetric digest
using a secret embedded in the customer client. Obfuscation or hashing cannot
make that design forge-resistant because generator and verifier share the same
secret. The correct serverless design is an Ed25519 signature: the internal
generator holds the private key outside the repository and customer builds hold
only the public verification key.

Removing the legacy verifier invalidates existing license keys and requires
reactivation. Retaining the legacy verifier preserves the same forgery path.
This is therefore an owner decision, not a safe implicit migration.

## Verification completed in this review

- Codec/Flow/build/Lite Viewer focused selection: 80 passed, 1 skipped before
  the external reference corpus was enabled.
- Explicit real compressed reference samples: JPEG lossless, JPEG 2000, and RLE
  all passed (3 passed).
- Installer legal/profile/ARM/candidate selection: 68 passed.
- Synthetic Inno compilation: Standard, ARM64-emulated, and Eagle Eye passed;
  missing Eagle Eye model rejection passed.
- Plugin mirror parity: 462 of 462 pairs matched.
- Isolated codec probe covered JPEG baseline, JPEG lossless, JPEG-LS, JPEG 2000,
  and RLE on Python 3.13.
- The combined affected regression selection passes 133 tests. The rebuilt
  PyInstaller Lite Viewer passes its frozen fail-closed self-test, is 120.2 MiB,
  contains GDCM/pyjpegls native payloads, and contains no `_libjpeg` binary or
  `pylibjpeg-libjpeg` distribution metadata.

The first frozen probe exposed an important packaging behavior: PyInstaller's
pydicom hook rediscovered the GPL codec from a dirty development environment
even after it had been removed from explicit requirements. The release and Lite
Viewer gates now reject that payload by name, and the clean build environment
has the distribution removed. This prevents a future implicit reintroduction.

## Required before a new final build

1. Decide whether all existing installations may be reactivated so the embedded
   shared-secret verifier can be removed.
2. Run the full affected source test lane and build preflight after that decision.
3. Create a new isolated source snapshot and build all three editions with both
   PyInstaller and Nuitka into the existing backend installer folders.
4. Verify frozen codec decoding, version resources, legal files, Slicer/model
   edition contents, checksums, and cross-backend coherence.

## Required before distribution

1. Confirm cardiac flow export in cvi42 using an authorized de-identified case.
2. Install each intended edition on a clean Windows machine and exercise Fast,
   Advanced, Slicer/MPR, Eagle Eye, import/export, and upgrade/rollback paths.
3. Test the ARM64-emulated installer on real Windows-on-ARM64 hardware.
4. Resolve Qt licensing/compliance and include complete license texts.
5. Complete credential rotation/history-cleanup evidence required by the
   repository security audit.
6. Authenticode-sign the approved installers, then regenerate all hashes and
   manifests because signing changes their bytes.
7. Obtain explicit owner production approval.

## Rollback

Keep the existing 3.6.5 installers and their manifests as superseded evidence.
Do not rename or promote them. A failed new candidate is discarded from its
isolated build workspace only; the working source and prior installer folders
remain intact.
