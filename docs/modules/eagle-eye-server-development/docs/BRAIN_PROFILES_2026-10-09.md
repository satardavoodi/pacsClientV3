# Four Brain connection profiles - 2026-10-09

## Shared Brain proxy - owner decision, 2026-10-12

AI > Connection > Eagle AI Brain owns the shared Direct/SOCKS5 setting and loopback proxy port. The private Brain settings are authoritative for G and Custom calls, including legacy company services. Caller proxy overrides cannot bypass this selection. Proxy failure never retries directly. A/V remain unqualified and cannot send inference; their optional transport probe must not bypass an enabled proxy. Existing private proxy values are retained; roaming Client personal settings are a separate store and are not bulk-copied. Server EchoMind hides its former proxy controls; Client personal API controls remain separate. Speech routing is unchanged.

AI > Connection > Eagle AI Brain exposes Server 1 - LLM G, Server 2 - LLM A,
Server 3 - LLM V, and Custom API. Vendor/hardware routing names remain internal.
LLM G preserves existing company models/prompts and center-code authentication.

LLM A/V are reserved connections, not inference-ready providers. Their private
brain_routes host/port records support a bounded TCP probe only. Selecting them
rejects inference before provider contact; there is no automatic company fallback.
A100 WAN 8082 is recorded in the infrastructure router map. No V100 public LLM
API port is verified; its public SSH 22293 is not an LLM endpoint. Owner input is
pending. Do not invent or copy the localhost 8096 service as a WAN inference API.
The existing A100 EchoMind legacy API is not a qualified new LLM A adapter.

Custom API uses administrator-entered own key, HTTPS base URL, optional OpenAI
organization/project, text/report/vision models and explicit own prompts. The
existing OpenAI/prompt controls are hidden in the Server EchoMind page; the new
private form owns saving under AI Connection. Blank key input retains an existing
private key, and snapshots never return that key. Company model fields remain
unchanged. No credentials are copied between hosts or into build inputs.

Current Custom API contract is OpenAI-compatible chat completions. It replaces
company system/developer prompts with the explicitly saved own workflow prompt,
uses the custom model, and retains user input plus structured response constraints.
Unsupported Responses/image-generation/native Assistant bodies fail without a
silent provider switch. They are not claimed migrated. Custom failures cannot
invoke the company report fallback. Token/call accounting is separated by profile;
legacy ledger rows migrate as LLM G. Native speech keeps its existing separate
registry identity and provider order; a custom LLM key never becomes a company
speech credential. This is a server-only settings/provider implementation with
unchanged mobile wire APIs; Android/iOS client UI changes are not required for this
slice. Server activation is a separate shared-behavior acceptance gate.

## Shared Eagle Server ingress - owner decision, 2026-10-12

AI > Connection > Eagle Eye owns listener address and HTTP request/result port. One HTTP listener, default port 8002 when no explicit port exists, dispatches EchoMind, Secretary, CRM and imaging by route family. These modules do not require separate public listening ports. Existing explicitly configured diagnostic or deployment ports remain supported. CPU, RAM, admission and thread budgets remain in the Eagle Eye settings tab.

The bind address must be a local interface address or 0.0.0.0 for all local interfaces. A router-forwarded public static address belongs to client addressing/port forwarding; it must not be assumed to be an address assigned to a local network interface. Host-specific addresses and forwarding are not hardcoded into the product. Saving listener settings applies on the next controlled service start and does not change the current listener automatically.


## Usage completeness (2026-10-12)

Imaging usage derives module labels from the registered admission catalog, preserving known friendly labels and historical rows. Approved native company G Assist/Search calls also enter the shared Brain provider-call ledger. The provider ledger counts upstream attempts (including approved fallback attempts), while workflow usage counts accepted requests; these are different metrics. Pending/completed/failed outcomes and provider-reported tokens remain separate. Missing token usage stays unknown, never estimated. Historical sender identities are not reassigned. No pairing is required to read ordinary Eagle usage.
