# Native 2D white-matter lesion pilot - 2026-09-26

## User workflow and scope

The existing White-matter Lesions dialog offers an acquisition selector. Default
3D uses the existing LST-AI route. Explicit 2D uses MindGlide 1.3.0 on FLAIR;
T1 is checked for examination identity and input role, but is not a model channel.
Select existing study series, review DICOM-populated age/sex, choose clinician
context, then Analyze. Computation and PDF export stay off the GUI thread.
The result card supports Save PDF, report opening and native-mask review.
The native 2D pilot is not an automatic retry after a failed 3D run.

The model runner is server-only. Standard Client carries the selector, request
contract and result UI, not model weights. No new test feature flag is required.
The local Test Control Server is only a GUI test facility, not the analysis API.

## Scientific method selection

Goebl et al., *Enabling new insights from old scans by repurposing clinical MRI
archives for multiple sclerosis research*, Nature Communications 16, 3149 (2025).
https://doi.org/10.1038/s41467-025-58274-8
https://pmc.ncbi.nlm.nih.gov/articles/PMC11976987/
https://github.com/MS-PINPOINT/mindGlide

The final publication reports 4,247 training scans from 2,934 MS patients and
592 scanners; external validation covers 14,952 scans from 1,001 patients.
It explicitly addresses heterogeneous 2D/3D clinical MRI. Its available inference
code and weights make it a practical 2D candidate. These cohort sizes do not prove
superiority to LST-AI on our cases or establish sensitivity to small frontal lesions.
Do not compare Dice numbers across different validation cohorts as a head-to-head test.
BIANCA needs suitably matched training data; BIANCA-MS availability does not provide
an immediately interchangeable, fully qualified deployment. Keep LST-AI for the
existing 3D route rather than extending its acquisition gate without validation.

MindGlide code is MIT. The pinned Hugging Face weights repository did not declare
model-card licensing when inspected. Code licensing alone does not establish weights
redistribution permission. Development testing is separate from customer distribution.

## Admission and measurements

- Require original classic DICOM FLAIR with MRAcquisitionType 2D, one series,
  known uniform positive SliceThickness, regular physical positions and no overlap.
- FLAIR recognition retains the existing exclusion rules. TIRM dark-fluid with
  long inversion time can be admitted; STIR, plain T2, T1-FLAIR and irregular stacks cannot.
- Engineering pilot limits: in-plane spacing <=2 mm; slice step/thickness <=8 mm.
  These are implementation limits, not scientifically validated universal cutoffs.
- NIfTI-only input cannot establish acquired slab thickness and is rejected in this route.
- MindGlide internally resamples; returned anatomy must match the native FLAIR grid.
  Label 18 supplies the binary candidate mask. No hidden minimum-size removal is added.
- Primary sampled-slab burden = positive pixel count x dx x dy x SliceThickness.
  Secondary gap-inclusive estimate = positive voxel count x dx x dy x slice-centre step.
  Neither recovers unobserved tissue or provides exact continuous lesion volume.
- Report 8-connected slice components and 26-connected stack candidates separately.
  Neither count is a confirmed unique lesion count when thick slices/gaps can merge/split lesions.
- No borrowed 3D percentiles, automatic Fazekas grade, MS diagnosis or McDonald fulfillment.
  Regional entries are explicit unavailable values, not zero. A separate native-grid
  localization validation is needed before periventricular/juxtacortical/callosal and
  supra/infratentorial counts are qualified for this backend.
- SVD and other clinician contexts remain labelled unvalidated transfer from an MS-trained model.
- 2D longitudinal comparison is disabled. Registration, scan-geometry matching and
  new/enlarging-lesion validation are prerequisites for enabling it.

## API and ownership

Existing POST /v1/jobs module brain-lesions accepts parameters.acquisition_mode
as exactly 2d or 3d. Missing means 3d, preserving older callers. T1 and FLAIR series
references, source counts and StudyInstanceUID use the existing authenticated
PACS-reference contract. The client checks /v1/capabilities.lesion_acquisition_modes
before a 2D request. Capability advertises protocol support, not model readiness.
The worker still verifies model/runtime hashes and DICOM identities on execution.

The server owns source retrieval, inference, original results, PDF and masks. The
client downloads checksum-verified allowlisted artifacts. No DICOM/model bundle is
exported. A derived native FLAIR image and mask support review over the existing
paired, authenticated connection. Patient details and artifacts remain private.

2D results carry acquisition_mode, model/version/manifest hash, metrics.volume_basis,
slice geometry, sampled and grid volumes, slice and stack counts, review status,
clinical context and explicit lesion_topography availability. Short private scratch
paths isolate native libraries from Windows MAX_PATH. Publication uses extended
Windows file paths and writes result.json last. Failed outputs are marked FAILED.
The authenticated export path likewise uses extended paths for 2D files.

## Reversible smooth-band review follow-up

The raw MindGlide label-18 mask includes smooth periventricular signal; its presence
alone is not evidence of a focal MS lesion. `periventricular_band_filter.py` adds a
conservative post-inference review in the explicit 2D MS context. It does not change
the model, 3D LST-AI, acquisition geometry, SVD reports or other clinical contexts.

Scientific basis: Filippi et al., Brain (2019), doi:10.1093/brain/awz144,
https://pmc.ncbi.nlm.nih.gov/articles/PMC6598631/ describes symmetric linear bands
and caps as patterns not to count as typical MS lesions. This is not a license to
delete all periventricular signal. Smooth periventricular hyperintensities can also
represent real white-matter changes: https://pmc.ncbi.nlm.nih.gov/articles/PMC7966482/.
Neither publication validates our numerical classifier thresholds.

Version `paired-axial-bands-1` requires paired long, thin, approximately AP-oriented
bands tangent to the ventricular boundary, native in-plane spacing <=1 mm and axial
obliquity <=30 degrees. A broad, irregular, radial or unsupported slice protects
the whole connected component. Tiny <=3 mm end fragments cannot initiate exclusion.
Rounded caps and short, focal, unilateral or uncertain candidates remain for review.
The exact physical-unit parameters and component identities are stored in the result.
They were developed using one exploratory case plus synthetic controls, not a held-out
clinical validation cohort; no sensitivity, specificity or normal-tissue claim is made.

Publication preserves `labels-raw.nii.gz`, `labels-band-review.nii.gz` and retained
`labels.nii.gz`. These are an exact disjoint partition on the native grid. The PDF
shows raw, separated and retained sampled-slab burden; red means retained candidate,
amber means suspected smooth band, not confirmed normal tissue. The authenticated
artifact allowlist includes both additional masks. No original DICOM or model is exported.
Manual revisions do not rerun the filter. Changing MS to SVD/other restores the raw
mask in a new immutable report revision; switching an unfiltered context to MS requires
new analysis. Original results remain unchanged.
