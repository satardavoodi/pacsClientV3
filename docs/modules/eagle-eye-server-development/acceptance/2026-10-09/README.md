# Cross-platform Eagle Eye acceptance package

Use package.json on Windows source Client, authoritative Android and authoritative
iOS. Adapt fixtures through each native client, not a replacement HTTP client
presented as GUI acceptance. Each platform records every case as pass, fail,
blocked, or unavailable with reason; an absent UI entry is not a pass.

Run Windows, Android, then iOS sequentially after owner releases the matching
server target. Use synthetic inputs only. Do not save a report into real reception,
read clinical CRM records, run an Agent proposal, or replay a provider failure.
Record actual server requests/tokens across every upstream model; one client
submission can legitimately involve multiple server upstream calls. Never claim
one-to-one ledger counts without measuring. No raw clinical logs or credentials.

Current preflight: active education-presenter source responds to authenticated
capabilities, but lacks brain_connection.py and user_access configuration. Brain
settings select server_1, which alone does not prove central authority is running.
Candidate brain-profiles-r2 remains separate. Client GUI test-control ping failed.
All inference cases remain pending matched activation and valid user admission.

Package is a coverage manifest, not an executable test runner. Native adapters
must validate exact bodies and negotiated capabilities before submission. Full
EchoMind inventory includes Assistant/Search native company workflows and breast
assistant separately; do not flatten these to generic chat. Turbo is server-owned
report policy; no second Turbo button is introduced. Unsupported mobile tabs,
attachments, Agent execution and model fixtures must be recorded explicitly.
