# Windows ordinary Eagle authentication

The shared Eagle Client now uses captured current-login username/password followed by the server-issued opaque user session. It neither loads nor sends legacy paired-device bearer credentials or client certificates. A socket/provider token alone is not an Eagle login context. HTTP does not initialize optional TLS settings. Server identity resolution and local feature/module grants remain authoritative; the client sends no provider selection.

The existing successful Windows socket login publishes its socket identity, then captures username/password in process memory. PACS socket Login supports Reception/RIS authentication when that existing integration is configured, so a successful Reception-backed socket login uses the same capture path without a new form. Whether a particular deployment enables RIS and admits a Reception-only test account requires separate live qualification. No fake socket identity or viewer/PACS access is introduced. Main socket/viewer authorization remains unchanged.

Account/profile changes invalidate the opaque cache. Late ordinary HTTP 401 invalidates only its captured login generation, preventing an old response from clearing a newer login. Logout uses the original transport and opaque user session without a legacy device bearer. Native Server Secretary lease refresh and private child IPC remain intact. Mobile-to-Windows Agent PACS QR/HTTPS identity is a separate implementation and unchanged.

Automated evidence: seven initial regression cases failed before implementation; a late-401 case and HTTP-without-TLS case separately failed before their fixes. The final six-file focused suite passed 85 tests, exit zero, with no reruns. New guards cover password-only requests across imaging, Secretary, EchoMind and CRM; no legacy device credential loading; socket-token-only refusal; server-resolved authority in the deprecated compatibility helper; generation races; and actual Windows successful login capture for both authority labels. Synthetic fixtures only. Scoped packaged mirror synchronization found zero matching mirrored parents for the three runtime paths.

No live login, GUI restart, Razi activation, release build or device acceptance was performed. Exact immutable source staging, active Razi parity and affected Windows GUI/business acceptance remain separate coordinator gates.
